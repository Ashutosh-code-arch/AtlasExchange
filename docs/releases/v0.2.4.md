# Atlas Exchange v0.2.4 — Capped-Beta Human Verification

## Highlights

- Cloudflare Turnstile Managed protection for public registration, verification-email resend, and
  password-recovery requests.
- Mandatory API-side Siteverify validation with exact Worker hostname and action binding. Fabricated,
  expired, replayed, wrong-host, and wrong-action tokens cannot reach Identity use cases.
- Fail-closed behavior for provider timeouts, network failures, non-success responses, and malformed
  decisions. Existing origin checks and rate limits run before provider verification.
- Runtime-injected public site key, API-only secret key, narrowly extended Worker CSP, accessible
  light-theme widget, and fresh-token reset after every submission attempt.
- Demo API and gateway configuration refuse to expose public account actions unless their respective
  Turnstile key is configured.

## Deployment notes

- Publication scope: **API only**. The frontend and gateway deploy together as the existing
  Cloudflare Worker/static-assets revision; no web container is requested. The metrics collector is
  unchanged and excluded from this release.
- No database migration: expected schema version remains 15.
- Publishing does not create a Turnstile widget, update Render/Cloudflare, send email, or enable
  signup/recovery.
- Create a Cloudflare Turnstile Managed widget restricted to the exact production Worker hostname.
  Store `TURNSTILE_SECRET_KEY` only on Render and `TURNSTILE_SITE_KEY` only as the Worker's public
  configuration. Never place the secret key in Worker variables or source.
- Deploy both keys and the v0.2.4 API/Worker while `PUBLIC_REGISTRATION_ENABLED=false` and
  `PUBLIC_PASSWORD_RECOVERY_ENABLED=false` on both providers. Verify readiness, runtime
  configuration, CSP, and direct-origin rejection before any controlled account-flow test.
- The previously recorded collector finding is not fixed or waived by this release. A passing
  API-only gate is not evidence that the entire container set is clear.

Atlas remains a simulation: no real custody, deposits, withdrawals, or external order execution.
