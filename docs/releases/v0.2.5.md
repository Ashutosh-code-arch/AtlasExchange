# Atlas Exchange v0.2.5 — Turnstile Composition Fix

**Classification:** Reference

**Status:** Released

**Release date:** 2026-09-05

## Summary

v0.2.5 fixes the identity-module composition defect discovered by the v0.2.4 capped-beta activation
gate. The API now forwards its configured server-side human-verification adapter into the public
registration, verification-resend, and password-recovery HTTP boundary.

## Security correction

- Fabricated, missing, action-mismatched, and hostname-mismatched Turnstile tokens fail closed before
  public account behavior executes.
- Provider failures remain a temporary-unavailability response rather than bypassing verification.
- A PostgreSQL-backed composition regression proves that a rejected challenge does not create an
  identity.
- Public account flows remain disabled during deployment and are reopened only after the immutable
  API image passes the live fabricated-token gate.

## Scope

This patch changes composition wiring and regression coverage only. It does not change the database
schema, session model, 20-identity admission ceiling, SMTP behavior, or simulated-trading semantics.

## Deployment order

1. Publish and deploy the immutable v0.2.5 API image with public account flags disabled.
2. Confirm readiness, existing-user access, and direct-origin rejection.
3. Enable only the API flags and prove that a fabricated Turnstile token is rejected without creating
   an identity.
4. Deploy the matching Worker configuration and re-run the positive hosted challenge checks.
5. Record the final account-count delta and close the activation record.
